# SPIP V2 -- Business Requirements Document (BRD)

# Part 3 -- Enterprise Platform, Decision Support & Non-Functional Requirements

## 26. Enterprise Platform

The following enterprise capabilities shall be preserved from the
existing SPIP platform:

-   Authentication
-   JWT Security
-   RBAC
-   Admin Panel
-   User Management
-   Dashboard Framework
-   Reports Framework
-   Notification Framework
-   Manager Queue
-   Multi-Plant Support
-   SAP Connectivity
-   Docker Deployment

Only the planning business logic shall be replaced.

------------------------------------------------------------------------

## 27. Dashboard

### Business Requirements

Display: - Planning KPIs - Material Criticality - Production Readiness -
Forecast Summary - Procurement Summary - Planning Readiness

------------------------------------------------------------------------

## 28. Reports

Support: - Planning Reports - Inventory Reports - Forecast Reports -
Production Reports - Procurement Reports - Allocation Reports

Export Formats: - Excel - CSV

------------------------------------------------------------------------

## 29. Notification & Approval Workflow

### Business Requirements

-   Notification counter for unread notifications.
-   Manager Queue pending approval indicator.
-   Planner → Manager → Vendor approval workflow.
-   Complete audit history.

------------------------------------------------------------------------

## 30. Explainability Engine

Every recommendation generated by SPIP shall provide an explanation
describing: - Why the recommendation was generated. - Which business
conditions triggered it. - Recommended planner action.

------------------------------------------------------------------------

## 31. Planning Simulation

### Business Requirements

Support "What-If" analysis by allowing planners to simulate: - Demand
changes - Vendor changes - Lead Time changes - Capacity changes -
Storage changes

Simulation results shall not affect production planning data.

------------------------------------------------------------------------

## 32. Business Rules

SPIP V2 shall implement: - RMPM Statistical Planning Logic - RM Totality
Rules - PM Override Rules - Procurement Rules - Allocation Rules - Auto
Master Generation Rules - Planner Approval Rules

------------------------------------------------------------------------

## 33. Non-Functional Requirements

### Performance

-   Fast planning execution.
-   Efficient large file ingestion.

### Security

-   JWT Authentication.
-   RBAC.
-   Audit logging.

### Scalability

-   Dynamic server load balancing.
-   Horizontal scaling.
-   Background workers.

### Reliability

-   Monitoring.
-   Logging.
-   Backup.
-   Recovery.

------------------------------------------------------------------------

## 34. Future Roadmap

-   AI-assisted recommendations
-   Vendor Portal
-   Mobile Application
-   Advanced Forecasting Models
-   Power BI Integration
-   Multi-company support

------------------------------------------------------------------------

## 35. Conclusion

SPIP V2 transforms the existing SPIP platform into an enterprise
planning and procurement decision-support system by preserving the
enterprise platform while replacing the planning core with the validated
RMPM statistical planning logic and introducing enterprise data
intelligence, proactive planning, reactive planning, intelligent
procurement recommendations, and dynamic procurement allocation.
